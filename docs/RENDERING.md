# Rendering contract

## Coordinate systems and state

The camera sees a signed-distance scene, with one scalar unit treated consistently as a model-space distance. The graphic is not calibrated to physical metres or photometric lumens: the power slider is a relative radiometric scale. Local node count, camera, shell shape, phase and all post-processing are parameters, not hidden renderer state.

The seed is an exact 24-bit integer. Integer PCG hashing determines its phase and sensor-grain pattern. `time / duration` determines a periodic phase explicitly in `motion.y`; no wall-clock animation is used. The uniform layout remains `16 x vec4f`, with no added binding: `view.z` now carries `perforation`, `emit.x` carries `holeWarp`, `emit.w` carries `holeFrequency`, and `finish.w` carries `holeSoftness`. These repurpose unused channels; `emit.y` remains the renderer-owned sample index. `src/gpu/uniforms.ts` is the single packing definition. Export takes a cloned snapshot before any asynchronous work.

Primary rays use top-origin full-frame pixel positions. Aspect, framing and noise coordinates are based on the complete image, even when the GPU renders an overlapped tile. Ray march budgets are 64/104/160 for draft/balanced/final; medium budgets are 12/24/48 and visibility budgets 10/16/24. They are approximation budgets, not accuracy proofs. Conservative distance steps reduce overstepping; deformed SDFs are approximate distance bounds rather than mathematically certified SDFs.

`scene` selects ten forms: 0 Prometheus, 1 Commons, 2 Hearth, 3 Relay, 4 Knot, 5 Gyroid, 6 Droplets, 7 Reliquary, 8 Sanctum, 9 Corona. IDs 0–8 retain their original body geometry when `perforation` is zero. Reliquary joins an open subtractive crescent to a tapered, fluted shaft and three finite collars; Sanctum uses five depth-staggered, flared arch ribs around an open portal, not a literal figure. Both use the existing seed/time transform, thickness, spread and twist; Sanctum's bound expands conservatively with spread. The Selene, Oracle and Eidolon studies respectively emphasize cyan diagonal backlight, ivory dot matrix and blue-black etched bloom. Study/preset IDs remain separate (for example, `hearth` uses Knot). Recipe format/version and engine remain `hyalos-visual` / `1` / `hyalos-prometheus/1`. Import fills all four optical defaults only when all four fields are absent: `transmission: 0`, `ior: 1.5`, `dispersion: 0.008`, `absorption: 0.35`. Partially supplied optics are invalid. A missing `sampleGrid` migrates independently to 2. Migration preserves settings, not historical shader pixels.

Recipes missing both `beam` and `beamAngle` migrate independently to `beam: 0`, `beamAngle: 26`; partially supplied beam settings are invalid. Current authored defaults use `beam: 0.65`, `beamAngle: 26` and `dispersion: 0.004`, distinct from historical migration values. Study palettes and settings are art direction, not measured material/light data.

Corona uses XorDev's ORB-31 smooth subtraction of an unwarped sphere and a sinusoidally warped sphere. The installed `vendor/shadercn/components/orbs/orb-31/gpu.ts` is retained verbatim against `vendor/shadercn/orb-31.registry.json`. `scripts/compile-orb31.mjs` checks that equality and uses TypeGPU to generate the original `smin` and `coronaSDF` helpers into `src/shaders/vendor/orb31.wgsl`; `src/gpu/shaders.ts` imports those helpers into the shared scene shader used by preview and export. The upstream source SHA-256 is `13281ce0ac952dc3fb64c5729877a413e3d381d837c4206764e5cd8ed3f7f375`. ORB-31 is by [XorDev](https://x.com/XorDev), ported for Orbkit with permission: **non-commercial use only, with attribution**. The generated helpers and marked derived geometry are not covered by the MIT license on Hyalos's original transport or shadercn's runtime.

The integration keeps ORB-31's radius 2.6 and default warp divisor 0.9, frequency 5.25 and smooth-subtraction width 0.42. Corona applies a uniform scale of `0.55 * spread` and invertible seed/explicit-time rotations around the supplied field. It does not import ORB-31's full renderer, shearing tumble, audio inputs or animated parameter swings. Existing forms instead subtract a warped copy of their own body using the same warp and generated smooth-min helper; `perforation` interpolates the signed field from the original solid to that carved field. Zero bypasses carving exactly; Corona is already carved and ignores this amount. These are real body holes shared by primary, visibility and optical queries, not a transparency/noise mask or post effect. Emitters are separate geometry and are not carved. Conservative march scaling is separate from the signed surface field; deformed original forms remain approximate distance bounds, not certified SDFs.

The controls are `holeWarp` (0.3–10, a divisor: larger values reduce displacement), `holeFrequency` (0.15–30), `holeSoftness` (0.015–4) and `perforation` (0–1, other forms only). Defaults are respectively 0.9, 5.25, 0.42 and 0. Recipe import supplies these values only when all four fields are absent; any partially supplied group is invalid. Geometry/light edits wait for Render; a saved study image is not proof of the new geometry.

`sampleGrid` 1/2/3 integrates 1/4/9 complete scene rays at deterministic subpixel cell centres, averaging linear HDR radiance before optical/display processing. Each ray is submitted separately for the current chunk. For grids 2/3, a reusable GPU storage buffer retains per-pixel f32 sums in row-major subpixel order; the first ray initializes each sum, and the final average is converted to half-float for HDR assembly. Grid 1 directly evaluates the centre ray without using the sum buffer. Draft always uses one ray without changing the recipe. Balanced/final use the authored grid (default 2). This is spatial supersampling of one fixed scene snapshot, not temporal accumulation or a promise to eliminate all aliasing.

## Materials

The opaque microfacet BRDF uses roughness-squared GGX and correlated Smith visibility. Schlick Fresnel interpolates between dielectric F0 = 0.04 and the authored metal reflectance, controlled by metallic weight. Lambert diffuse is weighted by `(1-F) * (1-metallic)`. The shader multiplies the BRDF by incident intensity, the surface cosine and inverse-square distance attenuation. The glass/opaque mixture weight is `transmission * (1-metallic)`, so fully metallic material has no glass transmission.

The key light is a four-point quadrature approximation to a finite luminous region. Its sample weights sum to the configured key-light budget. A fill source and finite local emitters also contribute. Visibility is queried using the same scene geometry and stops at emitter boundaries, not the light centre. A finite visibility step budget can miss a distant blocker. Emitter falloff is approximated by an isotropic point source outside a visible finite sphere; very near that sphere, this is not the exact solid-angle integral.

`beam` (0–1) blends the key's isotropic angular profile with a cone aimed from the key centre toward the origin. `beamAngle` is its outer half-angle (integer 8–60 degrees); the fully lit inner half-angle is 80% of that. The cosine-space smoothstep cone is normalized to mean 1 over the sphere, with peak `2 / (1 - (cos(outer) + cos(inner))/2)`, so narrowing the cone redistributes the existing key budget instead of adding a second emitter. All four finite-source surface samples share the centre's axis and this profile. The independent analytic studio panels used by glass are not a shadowed finite-source reconstruction.

Glass uses Snell refraction, exact unpolarized dielectric Fresnel and total internal reflection at body boundaries. Reflected and transmitted branches can cross multiple interfaces; radiance-mode IOR-squared factors are retained, including for paths ending on embedded emitters. Reflection/refraction normals come from the body, not the authored surface-detail perturbation. Reflections escaping the scene sample analytic distant studio panels and the background, not a loaded environment map. Roughness/detail broaden the studio reflection lobes with an approximate Gaussian convolution; they do not implement sampled GGX glass scattering or frosted refraction.

`ior` is the green reference index (1–2.5). `dispersion` (0–0.08) specifies the blue-minus-red IOR span in a Cauchy-like inverse-wavelength-squared approximation at 610/550/460 nm; channel indices are clamped to at least 1. Nonzero dispersion traces three channel paths; zero dispersion shares one RGB path. This is RGB dispersion, not spectral integration or measured optical glass data. `absorption` (0–4) scales `sigmaA = -log(clamp(linearMetalColor, 0.001, 1)) * absorption`. Beer–Lambert attenuation `exp(-sigmaA * distance)` applies to each internal segment, including total-internal-reflection segments. Distances use scene units, not metres; the metal palette supplies the transmission tint.

Draft/balanced/final permit 8/12/18 optical segments across the branch worklist, depth limits 4/6/8 and 51/73/104 march steps per segment. The branch stack holds eight pending rays, and weights at or below 0.0005 are discarded. Boundary sign crossings receive seven refinement steps. Unresolved paths and work left at a limit contribute zero, not invented environment radiance; dense glass can therefore darken or miss transport. Direct-light visibility remains an opaque geometry query: no refracted/colored shadow transport or caustics. There is no general diffuse indirect bounce or subsurface scattering. Metal brightness comes from directly evaluated illumination, not a painted rim-light term. These physical models and finite approximations do not make the renderer a physically exact light-transport simulation.

## Medium

Procedural Ashima simplex noise modulates an authored density envelope, not computational fluid dynamics. `beam` also blends the original carrier-following ribbon toward a broad radial stage haze that fades to zero at the scene bound, retaining vertical falloff and noise. This couples the beam control to art-directed medium shape rather than simulating a fixed physical atmosphere. Transmission for a segment is `exp(-sigmaT * distance)`. The medium's single-scattering albedo is 0.85 and its phase function is Henyey–Greenstein.

The camera-ray integral uses piecewise-constant midpoint samples. Incoming core radiance uses inverse-square falloff. With nonzero `beam`, key scattering uses one centre sample instead of the surface's four-point quadrature, with their summed intensity `0.72 * power / PI`, the same angular profile, inverse-square falloff outside a 0.9-scene-unit radius clamp, and HG angular scattering. An additional authored `beam` multiplier fades this key-scattering contribution to the legacy omission at zero; it is an attenuated transport approximation, not an additional light-energy budget. Neither source performs a second shadow or extinction march from each medium sample to the emitter, and the medium is not integrated along secondary glass paths. Consequently, shafts can leak through blockers; there is no multiple scattering or exact finite-area near-field transport. This deliberate approximation is separate from surface shadow queries and adds no volume march steps.

## Color and camera

Palette input is OKLCH. Out-of-gamut input is mapped by chroma reduction at fixed perceptual lightness/hue. The display gamut is sRGB, not Display P3 or HDR10. Converted linear values are the shader's reflectance and light-color inputs. Intermediate radiance is held in an `rgba16float` target; values can exceed 1. The extreme upper tail is clipped at 60,000 to avoid half-float overflow; this is a storage safety limit, not a physical bound. The displayed/exported image is 8-bit sRGB, not a floating-point EXR.

The finite optical kernel redistributes radiance with normalized weights. It is an art-directable approximation of camera scattering, not a measured lens point-spread function. Luminance-based Reinhard tone mapping, contrast and vignette precede the sRGB transfer function. Grain, dot matrix, Bayer dithering and phosphor are explicit graphic/camera finishes, not new physical illumination. The dots sample the same physical scene instead of replacing it with a random dot field.

Phosphor scanlines are resolution-filtered: their cosine amplitude is multiplied by `1 - smoothstep(PI/2, PI, frequency)`, where `frequency = PI / max(fullHeight/1080, 0.2)` radians per pixel. The modulation fades as it approaches the pixel Nyquist limit and is suppressed at or above it, retaining the 0.83 mean multiplier instead of aliasing unresolved scanlines into broad bands. This is a display-finish filter, not a change to medium sampling or physical illumination.

## Resource and export behavior

A real vGPU context owns the device, surfaces, a reusable HDR chunk target, a 262,144-byte (256 KiB) f32 sample-sum storage buffer, an assembled HDR sampled texture, readback target and two effects. The `low-power` adapter preference is advisory; it does not enforce a power or thermal limit. Targets and the sum buffer are reused; when the assembled HDR texture changes size, the post effect is rebound to its replacement and the old texture is destroyed. HDR and canvas pipeline signatures are prewarmed at startup; the export signature is prewarmed before the first export tile. Rendering does not read pixels or sample sums back to the CPU during preview.

Startup initializes the device and prewarms pipelines only: it does not draw or present any preview, and no automatic refinement follows. `ready` means initialization succeeded, not that an image exists; explicit image export is then available without first rendering a preview. `renderedSettings` remains null until an explicit Render completes. The viewport initially shows a labeled saved study reference, not a render of staged or restored settings.

The 20-second startup timeout covers module/device loading and compilation, with no first-draw or visibility-wait phase. Failure, detachment or supersession aborts startup and disposes owned surfaces/context; a device acquired after cancellation is immediately released. Device acquisition, pipeline compilation and already submitted native GPU work cannot be preempted by JavaScript, and a blocked event loop can delay timeout delivery. A timed-out or failed connection can be retried with Reconnect; this is not a guarantee that the driver recovers. Reconnect also initializes without requesting a frame.

Editor preview defaults to balanced: at most 500,000 pixels and 1024 pixels on either axis. Draft is capped at 230,400 pixels / 640 per axis; opt-in final at 1,000,000 / 1440. Scaling preserves aspect ratio subject to integer rounding, never exceeds DPR 1, and also respects the device texture limit. Composing is manual from startup onward: numeric/color controls, dragging, zooming, presets, recipes, undo/redo and quality changes stage state without drawing. Edits cancel queued or in-flight preview work at submission boundaries and retain the previous complete image. Resize scales the bitmap and stages the changed viewport; it does not resize the GPU surface or draw. Render explicitly requests one frame at the selected quality and current scene time. There is no timeline, playback or continuously advancing editor clock. Scene time and duration remain explicit recipe/API parameters used by stills and exact-time sequence exports. Pending changes clear only when a completed preview matches the current revision, selected quality and viewport.

Position, scale and in-plane rotation receive an immediate CSS bitmap approximation, relative to the last completed frame's settings or the selected saved study's authored settings. This transforms the image, not the scene: geometry, holes, lighting, orbit and finish are not updated until Render. Labels distinguish saved references, approximate framing and a last render with pending changes. Drag-to-pan and Ctrl-scroll-to-zoom work on the stage even before WebGPU is ready or when it is unavailable; export disables these editing gestures. A saved reference is never exported as a live image. `renderQueued` marks an explicit request waiting for visibility, cancelled work or pacing; the button shows Queued and blocks duplicate requests, distinct from an actively Rendering pass.

Timer scheduling allows at most 15 frame starts per second and waits at least the entire preceding draw's elapsed time after it finishes, including aborted draws. One preview draw is in flight; a new explicit request waits for cancelled work to drain and retains its owed rest. Idle scenes schedule no work, even with staged changes. Hidden tabs cancel preview work and stop timers; returning to visibility can resume only an outstanding explicit Render request, never create one for startup or staged changes. Export cancels preview requests and uses the staged state on the shared context. It neither clears pending canvas changes nor schedules a replacement preview afterward.

Both preview and export shade sequential chunks in a separate HDR target of at most 128 × 128 pixels, clearing the attachment for each sample pass rather than scissoring a larger render target. Chunk uniforms retain full-frame pixel coordinates. After a chunk's final sample, a GPU texture-to-texture copy places its averaged HDR texels into the assembled texture, with no filtering or intermediate display conversion; scene rays need no inner halo. The assembled texture still spans the full preview or overlapped export tile. Submitted work and GPU errors are drained after every primary sample, including the copy on the final sample, followed by a rest of at least 4 ms or twice the measured dispatch-through-drain wall time, whichever is greater. This cooldown survives cancellation before a replacement draw/export. It is not a GPU timestamp measurement. Cancellation is checked between sample passes and before the single full-target post pass; it cannot preempt an already dispatched sample/copy or post pass. Cancelled partial HDR work is not presented; the previous preview remains visible until scene shading completes. Splitting samples and pacing do not reduce final export shader quality or the authored sample grid, and high-quality glass exports can be slow.

Chunk sides are 128 for opaque material, 64 for active glass (`transmission * (1-metallic) > 0`), and 32 for active glass with nonzero dispersion; edge chunks can be smaller. Inactive dispersion on an opaque material does not shrink chunks. Side length is independent of `sampleGrid`: more rays produce more paced sample submissions, not fewer rays or larger per-submission ray loops. This is a submission-size heuristic, not a certified GPU-time bound.

Raster exports require integer dimensions from 64 to 8192 per side and at most 33,554,432 pixels. Default readback tiles are 1024 squared plus overlap, reduced to fit the GPU texture limit. The halo is `(3 * bloomRadius + dotSpacing) * fullHeight / 1080`, rounded upward with a 4-pixel margin. It covers the full optical kernel plus cell-centre displacement. Export tiles retain their global coordinates. GPU allocation is bounded per tile, but the CPU still assembles a full RGBA image: an 8K frame alone needs approximately 127 MiB, plus encoding and temporary buffers. Sequences additionally cap output at 2,073,600 pixels, 600 frames, integer 1–60 FPS and 1–60 seconds, with a 240 MiB accumulated encoded-frame limit (not a total-memory cap). Low-memory devices should use smaller outputs.

These are resource bounds and scheduling precautions, not guarantees against device loss, crashes, memory pressure, browser/driver watchdogs or thermal load. No real-time playback frame rate is promised. Higher resolution, glass dispersion and 4/9-ray sampling increase work. Hardware qualification and its limits are recorded separately in VALIDATION.md.

Readback checks the post pass's opaque-output contract: any alpha byte other than 255 stops rendering and rejects the export. Reconnect creates a fresh renderer after this failure; a failed browser/driver may still require reload. This catches incomplete transparent output but does not verify RGB correctness or repair the underlying GPU failure. Passing that guard is not hardware qualification.

No adaptive temporal accumulation or stochastic wall-clock samples are used, so a settled frame does not change simply because it was left open. Different quality budgets, output sizes or GPUs can still differ. The recipe records the engine ID and source SHA-256; a changed shader is an explicitly different rendering implementation.
